# Документация предметной области

## Перед исследованием кода

- Прочитай `GLOSSARY.md` в корне проекта, если он существует.
- В `docs/adr/` прочитай решения, относящиеся к затрагиваемой области.

Если документов нет, продолжай работу без предупреждений
и предложения заранее их создать. Навык domain-modeling создаёт
их по мере согласования терминов и решений.

## Структура

В проекте один контекст:

- `GLOSSARY.md` — термины предметной области.
- `docs/adr/NNNN-<slug>.md` — архитектурные решения.

## Терминология

В задачах, предложениях, гипотезах и названиях тестов используй
термины из глоссария.

Если нужного понятия нет, проверь, используется ли оно в проекте.
Реальный пробел отметь для последующей работы domain-modeling.

## Конфликты решений

Если предложение противоречит существующему ADR, явно укажи
документ, суть противоречия и причину пересмотра.
